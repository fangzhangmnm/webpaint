## 0. 为什么这件事现在是承重墙

三件事叠在一起，才把一个长期潜伏的问题顶成了宣发级风险：

1. **实测底账（2026-08-21）**：全仓**零** `navigator.storage.persist()` 调用——只有
   `src/gallery/gallery-shell.ts:133` 与 `:157` 两处 `navigator.storage.estimate()`。
   即：IndexedDB 全程是 **best-effort** 存储，浏览器有权在存储压力下整源驱逐。
2. **C2 拍板（2026-08-21）**：CPP 未过审 → 陌生人默认**关闭云端功能**。
   → 对首批陌生用户，**IndexedDB 是唯一副本**，没有第二层。
3. **受众事实（user 原话）**：「很多穷年轻人都只有 mobile 没有 pc」。
   → "文件在你自己机器上"这套安慰对这批人**不成立**：他们没有那台机器。

**家规锚**：数据安全词典序「云端不丢画 >> 当前操作不丢 > 自愈」；
**瑞士奶酪 = 每层承重**——不许拿"下层会兜底"当理由，做不到要显式写契约。
浏览器驱逐的特殊性在于：**它绕过 app 的一切逻辑**。store 的 §A 红线（dirty 永不被驱逐、
处处 If-Match、删除=移到 .trash）全都建立在"本地存储会一直在"这个假设上，而这个假设从未被验证过。

### B. 配额撞墙时会发生什么（**比驱逐更急**）

驱逐是"以后可能丢"；配额撞墙是"**这一次保存当场失败**"。后者更接近词典序里的"当前操作不丢"。

- 代码审计：全仓 `QuotaExceededError` 的处理点在哪？有没有？（含 `@internal/store` 库内）
- **保存写到一半配额爆了会怎样**：留下半个文件？旧文件已删新文件没写成？UI 报成功还是报错？
  （家规：UI 不许谎报成功；错误路径不许吞掉之后照报成功。）
- .ora blob 是大件——2k/4k 多图层几十上百 MB 很正常。**iPad 上几张画就可能顶到上限**，
  这不是长尾场景，是主线场景。要给出"几张画撞墙"的实测数字。
- 缩略图缓存（`src/gallery/cloud-thumb-cache.ts` 等派生 IDB）也吃配额——撞墙时谁先死？

## 2. 已知景观（**AI 记忆性认知，全部待验证，可能已过时**）

- **Safari / ITP**：对**未安装到主屏**的站点，script-writable storage（IDB / localStorage /
  Cache API / SW 注册）在约 **7 天无用户互动**后被清除；**装到主屏的 web app 据信豁免**。
  → 若属实，"引导装主屏"从 UX 建议升级为**数据安全措施**。**这条是全案最关键的假设，优先实测。**
- **Chrome**：`persist()` 无用户弹窗，按站点参与度/是否已安装等启发式静默授予或拒绝；
  best-effort 数据在磁盘压力下按 LRU 整源驱逐。
- **Firefox**：`persist()` 会弹权限提示（与 Chrome 的静默模式不同）→ 申请时机会影响用户体验。
- **配额**：Chrome 约为磁盘可用量的一个百分比；Safari 有较低的起始配额与提额行为。**数字必须现查实测。**
- **无痕/隐私窗口**：一律临时，关窗即失。

## 3. Grounding：Blockbench（user 点名的前辈）

user 原话「grounding 的看，blockbench 是一个好的前辈」。要抄的不是功能，是**它怎么解这道题**：

- 它是免费的网页 3D 模型编辑器，同时有可下载的桌面版；受众与我们高度重合（爱好者、game jam、穷学生）。
- **重点考察**：它把用户数据的**权威副本**放在哪？（据信是**文件优先**——存到磁盘，而不是把身家托付给浏览器存储。）
  若属实，这是对驱逐问题的一个结构性答案，而不是打补丁。
- 也看：桌面版怎么分发、插件生态怎么建、捐赠怎么做。这几条对我们的"封建/插件骑士"时期都是现成参考。
- **我们手里已经有一半的解**：无地骑士（v0.10.16 起「存为本地 .ora」已进导出 hub、Ctrl+S 存回原文件）。
  结论若指向"无云用户走文件优先"，那不是新建工程，是**把已有的路抬成默认路**。
