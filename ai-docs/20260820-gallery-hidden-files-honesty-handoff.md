## 1. 现状（v0.9.29 起）

- gallery 列表 = 白名单 `.ora`/`.zip`（app 层 filter，`gallery/cloud-image-model.ts` 的 `isDocPath`）。
  png/jpg/md/一切其他文件不显示。图片可经 `<wp-cloud-picker>`（导入入口）看见；非图片杂物只在 OneDrive 侧可见。
- 当轮动机（拍板原话方向）：「图片在gallery不可见，gallery还是干净的一个个画，不distract」。

## 2. 诚实性问题清单（grill 素材，按锋利度排）

1. **看似空夹其实有货**：夹里只有图片/杂物时，gallery 显示一个「空」文件夹 tile。
   用户在图库删这个「空夹」→ store 整夹进 .trash（可恢复，但用户不知道自己删了看不见的东西）。
   家规精神对照：「冲突必 surface / 不静默删」——这里删除本身走了 .trash 不算数据丢失红线，
   但**知情性**存疑：UI 让用户以为夹是空的。
2. **「作品占用」口径**：`store.files.usage()` 数 files 分区全部字节。picker 打开过的图片会被
   `autoCacheOpenedFile` 缓存进本地 → 算进「作品占用」，但 gallery 里看不见这些占用来自谁。
   文案「作品占用」承诺的是画作，现在混入素材缓存 = 口径开始漂。
3. **导出物积累不可见**（v0.9.30 云盘导出后更明显）：`画名-stamp.png` 逐次积累在画的夹里，
   gallery 永远不显示；用户只有去 OneDrive 或 import picker 才会撞见一堆导出历史。
4. **回收站视图反差**：listTrash 不做扩展名过滤 → 整夹删除后，回收站里**突然**出现生前从未
   在图库出现过的文件名（图片/杂物）。「死后可见、生前不可见」本身就是不一致的信号。
5. **改名/移动夹**：图库夹改名会把隐藏文件一起搬（store 语义，行为正确），用户无感知——
   通常无害，列出来备查。

## 3. 可能的方向（未评审，grill 时逐个过，别当结论）

- A. 维持隐藏 + **夹 tile 加计数徽章**（「+N 个非画作文件」）：不 distract 但不撒谎。删夹确认文案带真实件数。
- B. 维持隐藏 + 只在**删夹确认**时报真实内容（最小改动，把知情性集中在破坏性操作那一刻）。
- C. 图库加「显示全部文件」开关（用户指令才显示，平时干净）。
- D. 「作品占用」拆口径或改文案（作品 vs 素材缓存分行；或素材缓存挂清理按钮——它可再生）。
- E. 什么都不做：OneDrive 是完整视图，图库定位就是画作视图（当轮拍板的延长线）。
- 注意 feedback：判断类产品决定归人类；A-E 都要 user 选，AI 不预设。

## 4. grill 时要拉上的相关事实

- 删除=移 .trash（可恢复），红线本身没破——争的是 UI 知情性，不是数据安全。
- CC 工作流是隐藏文件的主要制造者（素材投放 + 云盘导出），量会随宣发后使用增长。
- `is-hidden.ts`（dot 项）是库级隐藏（安全网），与本 app 级白名单是两层，别混为一谈。
- 参考图囤积库独立项目若立项（iOS 相册级），会把「不可见文件量」放大几个数量级——本 grill 的
  结论最好连着那个项目一起想。
