# ADR-0003：版本更新前不推云（保持 consent-gated push）

> created 20260718
> 状态：**已决定 —— 维持现状，不改**

## 背景

真机事故（2026-07-18，very high）：版本更新之后打开着的画点保存，远端文件不一样；
用改名去自愈，自愈了但远端旧画消失了。

根因链的**触发器**是：SW 更新点「重载」→ `app.ts` 的 `onBeforeReload` → `session.save()`
→ `persist(false)`（`tryPush:false`，**只落本地并标脏**）→ `location.reload()`。
也就是说 —— **每次版本更新都必然制造一个「dirty + 内存谱系已丢」的状态**。

于是自然会想到：那让 reload 前顺手推一次云不就好了？

## 决定

**不改。** `onBeforeReload` 继续只落本地、不推云。

## 理由

1. **它是 ADR-0016/0018 的有意设计**：opaque Work 的 push 必须 consent-gated。
   用户点的是「重载以更新版本」，不是「上传我的作品」。在那个时刻替他做一次网络写，
   是把「更新 app」和「同步作品」两件事偷偷绑在一起。慢网下还会让重载卡住。

2. **v433–v438 落地后，进入那个状态不再有害**：
   - 谱系能重捕（v432：`markSynced` 写 durable etag → `freshness` 的重捕守卫进得去）
   - 真推不上去时 surface 冲突面而不是死路（v432：`surfaceCollision`）
   - 失败时 UI 会说实话（v433：`isPushPending` + 徽章第四态；v436：接缝不再收窄成 void）
   - 改名不再吃掉远端旧画（v432/v433：谱系不明降级为「另存」+ 判据在 push 后重取）

   触发器还在，但它通向的已经是一个**可恢复、且被如实告知**的状态。

3. **方向问题**：为了少进这个状态而松动 consent 语义，是拿红线换便利。
   优先级是词典序的 —— OneDrive 不丢画 >> 当前操作不丢 > 自愈。这里没有任何一级受益。

## 被否决的替代方案

- **reload 前静默 push**：违反 consent-gated（上面 1）。
- **reload 前弹框问用户要不要推**：在「点了更新按钮」之后再插一个模态，是把一次点击变成两次；
  且离线时这个框只能报失败，纯噪音。
- **把 dirty 状态本身消除掉**（reload 前不落盘）：更糟，那是丢用户的笔画。

## 复查条件

若将来 `onBeforeReload` 之后出现**新的**不可恢复路径（即 v433–v438 的四条保证有任何一条失效），
重新审视本 ADR。否则不要再提。
