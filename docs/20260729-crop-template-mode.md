# 裁剪·模板模式（装裱/取景）设计定稿

> as-of v0.6.45 / 2026-07-29。与 user 三轮收敛后的终稿，**未开工**（排在 F 批 smartResample 字节化之后）。

## Reality（user 原话要点）

- 「裁剪比例不是绘制最后的时候发生，而是脑暴结束、试过多个姿势想好构图之后，开始放大到全图」
  —— 这是**定构图工具**，不是输出工具。必须轻、无仪式感。
- 「现有的剪裁/resize 不精确」根因 = 约束方向反了：目标尺寸是拖出来的结果而非写死的约束。
- 平时习惯是**移动窗口**（裁切框），不是缩内容。
- 打印机全是 borderless（自动 overspray ≈ 自动出血）→ 真需求是安全线不是出血。
- 无「裁剪并打印」流，无导出侧裁剪——只有画布内裁剪。

## 定稿

**入口**：裁剪工具加模式切换：`自由`（现状）/ `模板`（新）。

**模板模式（2B，user 拍板）**：
- 拖的仍是**裁切框**（交互与自由模式同族），但**比例被模板锁死**：拖角=缩放框、拖身=移动框。
- 无 rotation（user 砍，没必要）。
- 两个 fit 按钮（基准=**内容 bbox**，所有图层非透明并集）：
  - **填满**（cover）：框内缩到被内容盖满——结果无留白，出框内容裁掉；
  - **全含**（contain）：框外扩到含住全部内容——不丢东西，四周留空。
- 安全线参考线：框内缩 ~3% 虚线（borderless overspray 量级），可关。出血字段模板预留、UI 不做。
- commit =「裁剪 + 重采样到模板 px」**原子 op，保层**（每层同 rect 同缩放；裁完继续画）。
  确认按钮文案如实：「裁剪并缩放到 1200×1800」——不与普通裁剪装同一语义（有 rescaling）。

**模板 SSoT**（新建文档 / 模板裁剪 / 未来导出对话框共用一张表）：
- print 类：4×6 / 5×7 / A4 / A5 …（物理尺寸 × DPI → px，换算在 UI 亮出来）
- screen 类：1080×1920 / 方 2048 …
- pixel 类：32/64/128/256/512 …（「1024 草稿缩回像素」工作流）
- **自定义…**：输入 w×h（+单位 px/mm/in，print 单位时带 DPI）→ 走同一锁比框取景流程。
  与 resize 的分工（user 拍板两个都留）：resize=整图硬缩不改构图；自定义模板=先定目标再取景定构图。

**DPI 本体论（user 拍板）**：像素是画作唯一真相，DPI 只是输出解释——
- 存**模板**里（不是文档属性）；**ora 永不写 DPI**（防小白改乱 xres/yres 调不回）；
- 分享/导出 PNG 时写 pHYs chunk（当次从模板取；依赖自研/UPNG codec 落地）；
- desk 只记「本文档上次用的模板 id」（便利，无 DPI 语义）。
- 诚实注：borderless 驱动多为「缩放到整页」不读 pHYs——精确性的真来源是 px 比例=纸张比例。

**重采样（commit 单次）**：
- zoom=1 且整数位移 → 纯置换（逐字节无损，走 composeRigidWriteback 族）；
- 缩小 → step-halving 面积平均（**依赖 F 批 smartResample 字节化**；user：「缩到像素图也得鲁棒」）；
  像素模板整数比（1024→128=÷8）→ 严格 box 平均（user：面积平均可以）；
- 放大 → 双三次。

## 否决记录（别再提）

- 微信式内容动（2A）——被 2B 框动取代（贴移动窗口习惯、交互同族、实现最薄）；
- 内容 rotation——user 砍；
- 导出时裁剪——user 砍；
- 「导出副本」出口——只留「替换当前画布」（裁完要继续画）；
- DPI 进 ora——user 否（小白改乱场景）。
